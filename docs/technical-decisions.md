# Technical decisions

- **Dedicated Web Worker:** CSV parsing, inference, table search/sort, and chart aggregation stay off the UI thread. Keeping raw rows in the worker avoids repeated 100k-row transfers. Requests transfer a File reference and return compact metadata, pages, or aggregates. Simplicity is preferred to a multiworker synchronization layer. Cancellation is cooperative/result-discard based for synchronous computations; file replacement uses termination.
- **Zod:** one runtime contract protects provider output, saved widgets, imports, and shared configurations. Additional semantic checks verify column existence and compatible aggregations/date/filter/sort/pie usage. No AI expression evaluation exists.
- **Provider abstraction:** live HTTP is the default, while explicit mock mode keeps offline tests deterministic. Transport remains isolated from rendering and execution. AbortSignal and stage callbacks allow asynchronous loading and later genuine streaming without altering the UI.
- **AI Stack adapter:** the supplied Postman `/api/analyze` route restricts output to one metric. The server therefore uses its `/api/chat` route with InsightFlow's richer structured-output contract. Output is treated as untrusted, parsed and validated against actual columns; one correction retry handles malformed answers without hiding failures behind mock responses. Questions/schema/current configuration are the only remote inputs. Provider-generated arithmetic or narrative is not treated as a business result. Explicit follow-up language controls widget identity in application code; only edit requests include the current chart in model context. This avoids a live-model failure observed during testing where a new comparison inherited filters and overwrote the selected widget.
- **Small application-owned Node server:** shares API middleware with Vite and serves the production build without adding server dependencies. It bounds request size and concurrency, cancels disconnected requests and exposes no frontend secrets. Public hosting still requires HTTPS, authentication and client-specific rate limits.
- **Redux Toolkit:** cross-panel dataset metadata, selected chart, conversations, and dashboard configuration are shared. Keystrokes and table search state remain local. Large raw rows never enter Redux.
- **localStorage:** appropriate for compact, versioned configuration/preferences and bounded conversation history, not data files. Invalid versions recover safely. Debounced writes reduce layout-drag write frequency; quota/unavailable errors notify instead of crashing.
- **Optional IndexedDB via Dexie:** stores an explicitly opted-in File. Not enabled by default. Users can load or forget it. Nothing is sent to a server by this storage layer.
- **TanStack Table + Virtual:** table abstractions handle columns and sorting UI while worker-side operations keep the browser responsive. The UI requests 300-row windows and mounts only visible rows plus overscan. This is not 100k DOM rows or 100k Redux records.
- **React Grid Layout 1.5.4:** stable width/cols/layout API, resize handles, and explicit drag grip; controls cannot trigger dragging. Mobile stacks cards rather than squeezing desktop columns. Version 1.5.4 avoids the stray files shipped in 1.5.0–1.5.3.
- **Recharts:** presentation only. Real business calculations happen before rendering. Strict numeric inference prevents missing values becoming zero. Pie has safeguards; chart types share validated specs and stable IDs.
- **Tailwind 4 + shadcn-style Radix patterns:** tokenized light/dark theme, accessible Radix save dialog (focus/escape management), and a reusable CVA/Slot button primitive. Custom application styles keep the SaaS visual system consistent. No CDN fonts or decorative external assets are required.
- **Testing:** pure tests verify arithmetic/contracts/rules, component tests verify UI states, and real Chromium tests exercise the complete worker/provider/state/chart flow and 100k rows. No hardcoded performance promise replaces a real smoke test.

## Deliberate limits

The deterministic language parser is not a universal query language or forecast engine. Conservative CSV inference favors preservation over aggressive coercion. Only ISO date-only values are inferred as dates. Multiple numeric metrics are supported, but arbitrary calculated fields and categorical series pivots are not implemented. Current mock progress is stage-based, not token streaming. Dashboard persistence is local, not authenticated cloud storage. The worker caches up to 40 aggregate results keyed by nonvisual specification fields, clearing the cache on dataset replacement. Changing chart type or title reuses valid data while still checking pie-chart constraints. Larger workloads could add indexed/grouped column storage before introducing more workers.
